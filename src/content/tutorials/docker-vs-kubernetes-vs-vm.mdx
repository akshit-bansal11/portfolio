<Callout kind="note" title="Does Kubernetes still use Docker?">

Not directly. Since Kubernetes v1.24 (2022), nodes run containers through a runtime such as **containerd** or **CRI-O**, not through Docker Engine. Images you build with Docker still run fine, because both follow the same open **OCI** image standard. So: build with Docker, run anywhere.

</Callout>

## Common mix-ups

- **"A container is a lightweight VM."** No. A VM boots its own OS; a container is a process on the host's kernel.
- **"Kubernetes replaces Docker."** No. Docker builds images; Kubernetes runs them on a cluster.
- **"Containers are always safer than VMs."** No. VMs have the stronger wall, because each has its own kernel.
- **"Docker on my Mac runs without a VM."** No. Docker Desktop runs a hidden Linux VM, because macOS has no Linux kernel.
- **"Every project needs Kubernetes."** No. One server and Docker Compose run a lot of real products.

## DIY: see the difference yourself

Two short experiments: how fast each one starts, and whose kernel it uses. You need **Docker** (see [Docker 101](/tutorials/docker-101#install-docker)) and **Multipass** (see [VM 101](/tutorials/vm-101#diy-walkthrough)).

<Callout kind="warn" title="Windows readers">

Commands assume PowerShell. In PowerShell, plain `curl` is not the real curl, so wherever you see `curl` type `curl.exe`. When a step says to create a file, create it with an editor such as VS Code and save it exactly where the title bar says. Keep the contents exactly as shown: indentation matters in YAML.

</Callout>

<Steps>
  <Step title="Time a container" tone="docker" checkpoint="It prints hello. The first run includes downloading the small alpine image; run it again and it usually finishes in about a second.">

<Tabs group="os">
  <Tab label="Windows">

```powershell
Measure-Command { docker run --rm alpine echo hello }
```

  </Tab>
  <Tab label="macOS">

```bash
time docker run --rm alpine echo hello
```

  </Tab>
  <Tab label="Linux">

```bash
time docker run --rm alpine echo hello
```

  </Tab>
</Tabs>

  </Step>
  <Step title="Time a VM" tone="vm" checkpoint="It takes clearly longer than the container, even after the first download, because a whole OS boots.">

<Tabs group="os">
  <Tab label="Windows">

```powershell
Measure-Command { multipass launch --name cmp-vm --cpus 1 --memory 1G --disk 5G }
```

  </Tab>
  <Tab label="macOS">

```bash
time multipass launch --name cmp-vm --cpus 1 --memory 1G --disk 5G
```

  </Tab>
  <Tab label="Linux">

```bash
time multipass launch --name cmp-vm --cpus 1 --memory 1G --disk 5G
```

  </Tab>
</Tabs>

  </Step>
  <Step title="Whose kernel is it?" tone="amber" checkpoint="The VM prints its own Ubuntu kernel version. The container prints the kernel it is sharing: your own on Linux, or Docker Desktop's hidden VM on Windows and macOS.">

```bash
multipass exec cmp-vm -- uname -r
docker run --rm alpine uname -r
```

On Linux or macOS, also run plain `uname -r` to see your own machine's kernel. On Linux it matches the container's line.

  </Step>
  <Step title="Clean up" tone="red" checkpoint="multipass list no longer shows cmp-vm.">

```bash
multipass delete cmp-vm --purge
docker image rm alpine
multipass list
```

  </Step>
</Steps>
